# Фронтенд

React + TypeScript + Vite, стили на Tailwind CSS.

## Запуск

Нужны два процесса. Сначала бэкенд из корня проекта:

```
python manage.py runserver
```

Потом фронт:

```
cd frontend
npm install
npm run dev
```

Открыть http://localhost:5173

В разработке Vite проксирует `/api`, `/media`, `/admin` и `/swagger` на
`http://127.0.0.1:8000`. Благодаря этому фронт и API живут на одном origin,
CORS не участвует, а токен ведёт себя так же, как будет в проде.
Адрес бэкенда можно переопределить переменной `VITE_API_TARGET`.

## Демо-данные

Пустой каталог смотреть не на что, поэтому в бэкенде есть команда:

```
python manage.py seed_demo --with-user
```

Она добавит пять книг с изданиями, героями и мудбордами, а с флагом — ещё и
пользователя `demo` с паролем `demo-pass-12345`.

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | Дев-сервер |
| `npm run build` | Проверка типов и сборка в `dist/` |
| `npm run lint` | Линтер |
| `npm run preview` | Локальный просмотр собранной версии |

## Как всё устроено

```
src/
  api/        клиент, типы ответов и функции запросов
  auth/       контекст авторизации и защита маршрутов
  components/ переиспользуемые части интерфейса
  pages/      экраны
```

Заметки для того, кто будет править:

- **Типы в `api/types.ts` сняты с сериализаторов Django.** Меняешь сериализатор —
  поправь и здесь, иначе TypeScript будет уверенно врать о форме данных.
- **Обновление токена всегда одно на всех** (`api/client.ts`). На бэкенде
  включены `ROTATE_REFRESH_TOKENS` и `BLACKLIST_AFTER_ROTATION`, поэтому два
  параллельных обновления убили бы сессию: второе ушло бы с уже отозванным токеном.
- **Файл книги нельзя вставить в `<iframe src>`.** Эндпоинт требует заголовок
  `Authorization`, браузер пойдёт туда без него и получит 401. Содержимое
  тянется запросом и отдаётся просмотрщику как `blob:`-ссылка.
- **Цвет книги живёт в CSS-переменной `--accent`**, а не в inline-стиле каждого
  элемента. Задаётся один раз на корне страницы книги.
